# The versions this project is developed and tested against.
#
# Three files describe dependencies, and they answer three different questions:
#
#   pyproject.toml                    what is ALLOWED   (open >= ranges, library metadata)
#   constraints.txt (this file)       what is TESTED    (exact pins, applied with -c)
#   packaging/requirements-desktop.txt  what SHIPS      (the frozen desktop runtime)
#
# Install with the pins applied:
#
#   pip install -e '.[dev,cli,media,faces,pets,semantic]' -c constraints.txt
#
# or just `make setup`, which does exactly that. CI installs the same way, so a
# green run here and a green run there mean the same thing. Every pin below that
# also appears in requirements-desktop.txt carries the same number, deliberately:
# a model backend that behaves differently under a new onnxruntime or opencv is
# the class of bug this file exists to prevent.
#
# To bump something: change the pin, run the full suite AND the model-backed
# tests, and commit it on its own with the reason. Never bump as a side effect of
# another change.
#
# A constraint is not an install. Listing a package here pins it *if* something
# asks for it; it never pulls it in on its own.
